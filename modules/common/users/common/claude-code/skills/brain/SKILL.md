# brain — personal tracking store

The store lives at `~/brain` (plain markdown + git). It is global: this skill works from **any**
session — inside a repo, another repo, or none. Always operate on the absolute `~/brain` path, not
the current working directory.

Store conventions — bucket structure, page schema, workflows — live in `~/brain/CLAUDE.md`, the
working manual to follow for day-to-day operations. Frontmatter is written and validated by the
Nix-managed **`brain` CLI** (on `PATH`), which owns the schema; prefer it over hand-editing YAML.
The **canonical** copy of the manual, the CLI, and the store scaffold ship with this skill at
`~/.claude/skills/brain/templates/` + `brain.py`; `--sync` reconciles a store toward it. How to
route work to an external/team tracker is defined by the **active workspace's own rules** (e.g. a
repo's `.claude/` rules), not here. This skill is the generic mechanism.

## Procedure

1. **Read** `~/brain/CLAUDE.md` (the operating manual: structure, page schema, the `brain` CLI,
   workflows, guardrails — the source of truth) then run **`brain review`** (the current picture:
   focus, what's live, blocked, overdue, gone quiet, open tasks, pending inbox). Read `index.md`
   when you need the full catalog.
2. **Act** per the matching workflow in `CLAUDE.md`, using the `brain` CLI for all frontmatter:
   - **Capture/ingest** new info → process `raw/inbox.md` first if it has entries, then
     `brain new <kind> <slug> --summary "…" [--status …]` (or `brain set` on an existing page)
     files it in the right bucket with schema-perfect frontmatter **and a body skeleton for its
     kind**; hand-edit the page **body**; add it to relevant MOCs; record it with
     `brain log "<what changed> — [[page]]"`. (`index.md` is regenerated by the commit hook — no
     manual reindex needed.)
   - **Query** → `brain review` answers "what's going on" as a whole;
     `brain q [--status|--kind|--tag|--attention|--overdue|--due-before|--stale|--unverified]` for
     structured cuts, `rg` for free-text; pull open `dstask` tasks and any linked external issues
     when relevant; flag stale data; never invent. **Time-range** questions → `brain review --since
     DAYS`, plus the dated `log.md` (+ `log-archive/`) and `created/started/finished/due` filtered
     to the window (git log + dstask dates as backstops).
   - **Update status** → `brain set <page> status <value>` / `brain done <page>` (it bumps
     `updated` and stamps `started`/`finished`); when you've checked the page's claims against
     reality, `brain set <page> verified today`; reflect narrative in the body;
     `brain log "…"` (the commit hook reindexes).
   - **Review** → the recurring pass: `brain review`, then re-verify what's gone quiet, resolve
     contradictions, trim `mocs/now.md` down to judgment only, roll the focus pointer.
   - **Lint/reorg** → run the health pass (`brain check --strict`; split/merge/re-file;
     rotate `log.md` if large; `brain reindex`; flag contradictions).
   - **People** → `mocs/people.md` is the directory (table; columns are open, not required).
     Promote someone to a page with `brain new resource <slug> --person` once they outgrow a row.
     Person pages are excluded from `index.md` by design — they are not orphans.
3. **Personal tasks** (via dstask, driven by Bash):
   - `dstask add <desc> +<tag>` · `dstask` (list) · `dstask start|stop|done <id>`.
   - **Notes: use `dstask-note <id> "<text>"`, never `dstask note`.** The bare command gates on a
     controlling TTY and, run headlessly, **exits 0 while writing nothing** — no note, no commit, no
     error. `dstask-note` (Nix-managed, on `PATH`) wraps it in a pty and works on both hosts. Every
     other verb above is fine headlessly.
   - Cross-link: put `dstask:<id>` in the page's `links`; reference the page in the task note.
   - **Routing rule:** discrete personal next-action → dstask. Overall initiative state/narrative →
     a `~/brain` page (frontmatter + body). Work that belongs in an external/team tracker → that
     tracker, per the active workspace's own rules (e.g. its `.claude/` rules); link to it, don't
     duplicate.
4. **Commit** after any change:
   `brain check` first, then `git -C ~/brain add -A && git -C ~/brain commit -m "<concise message>"`
   (no AI attribution). The pre-commit hook regenerates + stages `index.md` and re-runs
   `brain check --staged`, rejecting malformed pages; a post-commit hook then pushes to the remote if
   one is configured (never force — on a rejected push, `git -C ~/brain pull --rebase` then push).

## Governance — the CLI, schema, and hook are Nix-managed

`brain.py`, the schema it enforces, and the `~/brain` pre-commit hook are **canonical artifacts
shipped from nixos-config** (`~/Develop/personal/nixos-config`, under
`modules/common/users/common/claude-code/skills/brain/`); the on-machine copies are read-only Nix
deployments. **If a check, the schema, or a hook needs to change** — a new `status`/`kind` value, a
new field, a relaxed rule, a different hook — **STOP and ask David to update the skill in
nixos-config**, then rebuild + `/brain --sync`. Never hand-edit the deployed CLI/hook, loosen a
failing check locally, or `git commit --no-verify` to bypass the gate. A failing gate means the
page is wrong (fix it) or the schema should change (David's nixos-config change) — never a local
workaround.

## Sync / migration (`/brain --sync`)

Run when invoked with `--sync` (or `sync`) — brings this machine's existing `~/brain` up to the
latest conventions after the skill/template/CLI were updated (e.g. by a rebuild).

1. **Read the canonical template** at `~/.claude/skills/brain/templates/` — especially its
   `CLAUDE.md` (the authoritative manual, structure, and page schema) and the `brain-template`
   version at its top. Confirm the CLI is on `PATH` and check the gap: `brain version`.
2. **Compare** against the live `~/brain` (its `CLAUDE.md`, bucket layout, page frontmatter).
3. **Reconcile in three commits**, so a bad step is revertible on its own. The store auto-pushes,
   so rollback is `git revert` of one tight commit — never a force-push.

   **Commit 1 — mechanical** (nothing is read for meaning; no judgment):
   - Create `.gitignore` and any missing bucket dirs / scaffold files (`mocs/now.md`) if absent —
     **never overwrite an existing one**.
   - Replace `~/brain/CLAUDE.md` with the canonical manual (the manual is canonical, not per-store).
   - `brain normalize`, then `brain check`; ensure `index.md` has the
     `<!-- BEGIN/END generated -->` markers and run `brain reindex`.
   - Untrack anything the new `.gitignore` covers (`git rm -r --cached __pycache__`).

   **Commit 2 — backfill** (judgment: show the diff and ask before applying):
   - Migrate page frontmatter to the current schema (add/rename/drop fields). Backfill `created`
     (and `finished` for done pages) from git where possible —
     `git -C ~/brain log --diff-filter=A --format=%ad --date=short -- <file>` for the first-commit
     date — and each page's `summary` from its existing `index.md` description line.
   - **v8 specifically:** backfill `verified` from verification stamps already written in bodies
     ("verified against the code 2026-06-24"); set `attention` where a page encodes it as prose
     (`**tracking only**`, `**main focus**`); lift trailing "Next step:" lines into `next`; split
     over-long `summary` fields into `next`/`progress` plus body; re-file `kind: adr` pages whose
     decision actually lives in a repo doc to `kind: project` (see the routing rule in the manual);
     tag person pages `person`.
   - `brain check` again to confirm the migrated store is schema-valid.

   **Commit 3 — stamp:** `brain version --stamp`, on its own, so "did the migration complete" is a
   single visible fact. Never stamp before the backfill lands.

   The commit hooks (pre-commit gate + post-commit auto-push) are installed by the rebuild that
   precedes sync; just verify they're present in `~/brain/.git/hooks` (a rebuild reinstalls them).
4. **Report** a summary and append it to `log.md`.

This touches only structure, schema, tooling, and the manual — **never the substance of pages**.
Trimming `mocs/now.md`, splitting an oversized page, or collapsing accumulated status sections is
content work for the REVIEW/LINT passes, not for sync. Git is the safety net; prefer mechanical,
reversible edits, and run the smaller store first.

## Guardrails

- Files are the source of truth; `brain reindex` keeps `index.md` consistent with the pages.
- **`brain review` writes nothing**, and no command rewrites a page body. Trimming `now.md`,
  splitting a page, or resolving a contradiction is a supervised edit you propose and the user
  approves — never a side effect of a read.
- Write frontmatter through the `brain` CLI; run `brain check` before committing; never bypass the
  gate. To change a rule, follow **Governance** above (ask David → change nixos-config → `--sync`).
- The post-commit hook auto-pushes to the remote when one exists. On a rejected push, reconcile
  (`git -C ~/brain pull --rebase`) and push again — never force-push or disable the hooks.
- **Dates come from the system clock, never inferred from the corpus.** The writers and
  `brain log` stamp dates automatically; use `brain today` (or `date +%F`) for any date you must
  supply by hand. A date seen in `log.md`/a page is a recorded fact, not today.
- Never fabricate status; mark gaps with `<!-- TODO: fill -->`.
- Never store secrets, credentials, or unnecessary PII.
